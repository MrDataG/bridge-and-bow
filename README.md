# Bridge & Bow Travel

Family cruise planning site: firsthand cruise reviews, port guides with affiliate tour links, and planning guides.
Live at **https://bridgeandbowtravel.com**, hosted on GitHub Pages.

The site is plain static HTML, CSS and JavaScript. There is no framework and no build step on the server.
One small Python script (`tools/build.py`) keeps the parts that repeat across pages in sync, and its output is committed.

## What the build script manages

`site/site.json` is the single place to change anything that repeats. Running `python3 tools/build.py` rewrites:

| What | Where it comes from |
|---|---|
| Header nav and its active state | every page in `site.json` (`nav` label, `section`, `active`) |
| Footer link columns | every page's `footer` label |
| Hub cards | the `hub` entry of each guide, in order, on the three section index pages |
| Home "Start reading" cards | the `home` entry of each page, sorted by `order` |
| Home stat counters | counted from the pages (guides, cruise lines, ports) |
| `<title>`, meta description, canonical, Open Graph, Twitter tags | `title`, `desc`, `og_image` |
| JSON-LD description, `dateModified` and article image | `desc`, `date`, `og_image` |
| `sitemap.xml` and `feed.xml` | every page (`date`, `freq`, `priority`, `published`, `feed`) |

Page **bodies** (the article text, photos and tour cards) are still hand-written in each HTML file.

Generated regions are fenced with `<!-- build:... -->` markers in the hub and home pages. Do not edit between them; change `site.json` instead.

## Adding a new page

1. Copy a similar page as a starting point (for example `ports/cozumel.html` for a port, or a review in `cruise-lines/`). Keep the shared CSS and JS links and fix the relative `../` paths.
2. Write the body. Keep the first-person facts to what we actually did, and say when something is research.
3. Add an entry to `pages` in `site/site.json`. A guide needs: `path`, `section`, `kind: "guide"`, `title` (60 characters or fewer), `desc` (120 to 155 characters), `og_image`, `date`, `published`, `freq`, `priority`, `nav`, `footer`, `hub` (kicker, title, blurb, cta), `feed`, and optionally `home` for the home page cards.
4. Run `python3 tools/build.py`. It adds the page to the nav, footers, hub, sitemap and feed on every page.
5. Run `python3 tools/build.py --check`. It exits with an error if a title or description is the wrong length, an image is missing, an HTML file is not listed in `site.json`, or any generated file is out of date.
6. Commit the page, `site/site.json` and everything the script changed.

## Affiliate links

- **Viator** (main program): partner id `P00314556`, `mcid=42383`. Link format:
  `https://www.viator.com/tours/<Destination>/<slug>/<code>?pid=P00314556&mcid=42383&medium=link&medium_version=selector&campaign=<page-slug>`
  with `target="_blank" rel="noopener sponsored"`. Use a different `campaign=` value per page so clicks can be traced.
- `assets/js/main.js` sends a GA4 `viator_click` event for any link to `viator.com`, using `.excursion-item .name` as the tour name.
- Tour cards use the `.excursion-item` markup (see `ports/nassau.html`). Prices and ratings go stale, so note the date they were checked.
- Castaway Cay is a Disney private island and has no Viator tours. Its activities are booked through Disney.

## Content rules

- Facts about our trips (ship, dates, rooms, what we did) come from us. If a page is research, a note at the top says so.
- Do not publish names, booking numbers, prices from receipts, or photo location data. Strip EXIF from photos before adding them.
- Photos live in `assets/img/trip/`. Pin-ready images (1000x1500) live in `assets/img/pins/`.

## Local preview

```
python3 -m http.server 8000
```

Then open http://localhost:8000.

## Cache busting

CSS and JS links carry a `?v=` value (currently `20261017b`). When you change `style.css`, `home-3d.css` or `main.js`, bump it in every page (a `sed` over `*.html` is enough) and update `asset_version` in `site/site.json`.

## Deployment

Pushing to the default branch publishes the site through GitHub Pages. DNS is at Namecheap: A records to GitHub's Pages IPs and a CNAME for `www`. See repository Settings, then Pages, for domain and HTTPS status.

## Analytics and consent

Google Analytics 4 (`G-EDJNC213VK`) is **off until a visitor clicks "Accept all"** in the cookie notice.

- `assets/js/analytics.js` sets Consent Mode to denied by default and loads `gtag.js` only when the stored choice is `all`. Do not add a `googletagmanager.com` script tag to any page; `tools/build.py` fails the build if one appears.
- The choice is stored in `localStorage` under `bnb_cookie_consent` (`all` or `essential`). "Essential only" sets no analytics cookies and clears any `_ga` cookies.
- Every page has the notice and a "Cookie settings" link in the footer to change the choice. Both are generated by `tools/build.py`.
- Policy text is in `privacy.html` (section 4 and 6).

The newsletter form posts to a Google Apps Script web app (the URL is in `assets/js/main.js`).
